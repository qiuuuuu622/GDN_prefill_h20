# 正确性、稳定性与测量协议

## 正确性证据分层

| 阶段 | 已有证据 | 不能据此声称 |
|---|---|---|
| 122B 混合 CP | 原报告：新增测试16通过；相关套件2990通过、866跳过；输出最大差≤7.8e-3、最终状态≤2.5e-3 | SGLang E2E 已测；此历史行与新0.6.18对照为同一次实验 |
| 35B 早期无 checkpoint V2 | 84 eager/graph 对原 non-CP 逐位等价；独立 FP32 34/36通过 | 所有高精度参考通过；可以替代 auto-CP |
| 35B 单序列 checkpoint | dense32、选定位置24、真实回放6、在线shadow720、memcheck4；已测输出/状态/checkpoint一致 | 所有 shape、多并发或模型质量全部通过 |
| 35B 最终多序列 | 合成72、planner映射277、GPU边界/回退9、memcheck8零错误、真实回放6、在线shadow900逐位一致 | 长期soak通过；真实服务覆盖过N8；端到端文本确定性 |
| 35B 16K候选 | 新增52合成、memcheck10零错误、shadow810一致 | 性能验收通过：实际已拒绝 |

对原版等价与独立高精度参考是不同保证。早期 near-one gate 的独立 FP32 检查有原版也出现的阈值失败，未放宽阈值隐藏；最终报告保留此限制。

**被拒绝的全路径 V 替换**：在真实 auto-CP 输入的最终状态上，9/524288 个元素违反 atol/rtol=0.02，最大违规绝对差约0.034626。这不证明 CP 本身错误，而是说明旧 V 候选不能在当前保证下替代它。最终版本仅优化 checkpoint，保留无 checkpoint auto-CP。[拒绝记录](../experiments/20261024-gdn-checkpoint-opt/results/rejected_candidate.json)。

memcheck 零设备错误不等于所有 racecheck 已运行；历史命令关闭了 CUDA API 查询返回码报告，保留设备内存和 stream-ordered 检查。早期默认 memcheck 的41条 API 查询错误仍在 shape-study 原始合成日志中。

## 固定负载与计时

- 35B 1P1D：GPU6=P、GPU7=D+DFLASH8，TP1，NIXL，BCG 保持。
- 固定十条来自122B业务测试数据，先删除图片块与占位符；不是随机代表性全量抽样。数据集选择说明与哈希公开，正文未公开。
- P FP8、D 4-bit，draft独立；因此不是“同一FP8模型全流程”的测试。
- temperature=0、seed=42、max_tokens=512，自然停止；不强制同输出长度。
- 最终实验每个P部署先用同十条预热形状；每个测量批开始清P/D前缀缓存，批内保留。清前缀缓存不等于清JIT/编译缓存。
- 每并发各执行AB、BA，两臂每轮10条，总每臂20条。闭环：一个请求完成后补下一个；不是固定到达时间的开环。
- TTFT：真正提交HTTP到第一个非空content/reasoning/tool片段；E2E：提交到流结束；TPOT=`(E2E−TTFT)/(输出tokens−1)`。保留原客户端定义，不等同于单个decode kernel时间。
- 分位数采用排序后线性插值。20条的P95/P99非常接近最慢请求，只用于描述本次样本。

## 收益稳定性与归因

最终多序列实验120/120正式请求成功，加预热/shadow/profile共260/260成功。C2两轮TTFT分别−7.64%/−8.16%，C4为+0.08%/−9.06%，C8为−1.87%/+13.55%。请求成功和算子正确性通过，不等于性能稳定。

API cached_tokens配对相同：C2 20/20，C4 12/20，C8 2/20；原脚本对未返回该字段的情形按0记录，不能把缺失字段当作可靠命中量。P batch日志提供另一层新token/缓存token证据，但也不是完整逐请求因果追踪。

输出文本跨运行可能不同，原版自身也有变化；所以本轮不是模型质量测试，E2E也不是固定相同输出工作量比较。相同输入长度、总缓存量甚至batch布局，均不足以证明执行时序完全相同。

单并发TTFT观测−12.64%不能全归因于GDN：sample01 profile中checkpoint GDN只直接节省约11.91ms，而另一次正式测量TTFT差值约275/305ms。两次测量不能直接相减来声称通信收益。C4两个profile的工作布局不同，同样不能据累计GDN时间比宣称算子加速。

共享主机其他GPU有任务，未操作；CPU/内存带宽等干扰不能排除。16K实验正式批次CPU cgroup新增限流周期为0，也不排除其他CPU竞争。

## 本次归档与新统一入口验证

归档检查包括来源hash、Python语法、三个新包生成内核与两个历史内核字节复现、360条正式请求的分位数重算、文档链接和公开数据字段检查。

新增统一入口在GPU6执行差分、graph和内存测试，结果独立归档在[入口验证](../experiments/20261024-unified-entry/README.md)。两种geometry的统一checkpoint原实验有240/240 exact核心检查；新CP边界实验112/112相对原CP前缀逐位检查、200/200动态回放、32项memcheck零错误。但其near-one对non-CP仍有失败，所有原始结果保留。[CP数值限制](checkpoint-contract.md)。

本次没有启动模型服务或新做端到端AB；历史35B服务结果不能作为新公共入口已经部署验证的证据。
