## 如何解读变化

均值、P50、P90、P99分别描述延迟分布的不同位置，不要求下降比例相同。前轮单并发中sample01/02贡献约70.3%的总配对TTFT节省，而最慢请求几乎不变，因此P90下降大、P99下降小。20条样本的P99接近最大值，容易被单条波动左右。

并发测试还引入请求排队、合批、完成顺序与前缀可用时机变化。闭环端到端结果描述这套实际运行方式；缓存/批布局不一致时，无法把差值隔离归因于GDN算子。即使总缓存相同，单请求分配和GPU调度也可能不同。
- C2：两轮平均TTFT相对变化分别-7.64%、-8.16%。仅两轮，不能作为长期稳定收益的证据。
- C4：两轮平均TTFT相对变化分别+0.08%、-9.06%。仅两轮，不能作为长期稳定收益的证据。
- C8：两轮平均TTFT相对变化分别-1.87%、+13.55%。仅两轮，不能作为长期稳定收益的证据。

## 新实现与算子证据

1. 为每条序列构建“输出槽位、保存token位置”的紧凑元数据；只写缓存消费者实际要用的状态，最终状态仍全部写出。消费者索引同步重映射，已与原版planner逐项核对。
2. 同时保留完整V128和DV64内核；每个batch按各序列的64-token块数、32/64个CTA及78个SM估算负载。多序列只有预测DV至少快15%才选DV，否则选完整V。选择结果按长度元组缓存，不在每层同步序列长度到CPU。
3. 无checkpoint的auto-CP路径保持原版；不支持的形状回退原版。私有负间隔-1/-2及交错metadata只在本地adapter/kernel内部使用，不是FlashInfer公共API。
