## 后续优化方向（本轮未执行）

- 保持8K、新GDN及其他参数，单独验证P的缓存感知调度，例如FCFS对LPM；目标是减少共享前缀请求在可复用状态形成前的重复prefill。当前schedule_policy.py含waiting-queue前缀匹配及共享前缀降优先级逻辑，但在本负载上的收益尚未测量，公平性和尾延迟必须一并验证。
- 端到端归因需要关联每请求的P排队、GPU执行、KV交接和D首token时间；客户端TTFT、总新tokens及聚合batch日志不足以完全定位时序波动。
- 继续保留同输入真实GDN回放作为算子证据。固定到达时刻/固定输出长度只适合单独诊断，不替换本轮真实闭环自然输出数据。
- 本安装版本enable_dynamic_chunking用于PP；gdn_backend.py还会因该开关退出默认FlashInfer选择，因此不把它当成TP1并发优化的一键方案。源码快照见evidence/。
